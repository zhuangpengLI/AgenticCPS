# CPS 平台配置中心设计

**日期：** 2026-07-23  
**状态：** 已完成产品方案确认，等待书面规格审阅

## 1. 背景

当前新平台接入需要分别进入 API 供应商管理、平台配置、推广位管理和返利配置四个页面。四类配置通过 `platformCode` 逻辑关联，用户需要理解隐藏的创建顺序，并在多个页面之间往返补充主供应商、默认推广位和连接测试。

现状还存在以下体验和一致性问题：

- 菜单顺序与实际配置依赖不一致。
- 平台、供应商和推广位选项在多个前端页面硬编码，支持范围不一致。
- 平台默认推广位、供应商备用推广位和推广位 `isDefault` 分散配置，容易产生归因偏差。
- 供应商凭证只能在保存后通过平台连接测试间接验证。
- 返利配置直接暴露会员等级 ID、优先级等高级概念。
- 四组独立接口串行提交会留下半配置状态。
- 已有平台重配会直接影响运行配置，缺少测试通过后再切换的安全机制。
- 没有统一的配置完整度、连接状态和待办提示。

## 2. 目标

建设一个统一的“平台配置中心”，替换现有四个管理页面的菜单入口，同时保留平台、供应商、推广位和返利配置的列表及增删改能力。

平台配置中心必须支持：

1. 新平台首次接入。
2. 已有平台重新配置。
3. 一个主供应商和可选的多个备用供应商。
4. 通用、渠道专属和用户专属推广位。
5. 必填的平台默认返利比例，以及收进高级设置的会员等级、金额上下限和优先级。
6. 检测失败后保存为待完善、禁用草稿。
7. 已有平台在草稿检测通过后原子切换到新配置。
8. 平台配置的查看、新增、编辑、检测、启停和删除。

## 3. 非目标

- 不通过数据库配置动态生成一个尚未实现后端适配器的平台。
- 不在本期实现供应商运行时自动故障切换；备用供应商仅完成配置、优先级和可用性管理。
- 不修改 CPS 订单归因、返利结算、冻结扣减或 Token 兑换的业务规则。
- 不删除旧的四组后端 CRUD 接口；它们暂时保留兼容，但不再作为菜单入口。
- 不在统一向导中管理全局返利、会员个人返利或与当前平台无关的规则。
- 不删除或改写历史订单、返利、结算和审计数据。

## 4. 方案选择

采用“平台配置中心 + 全屏配置工作台”。

未采用的方案：

- 单页主从布局：操作快但信息密度过高，不适合首次接入和复杂凭证配置。
- 纯向导：首次接入清晰，但已有平台只修改一项配置时维护成本过高。

统一方案同时服务两类用户：

- 新用户按五步向导顺序完成接入。
- 熟练用户编辑已有平台时可直接切换到任意配置页签。

## 5. 信息架构

```text
联盟配置
└── 平台配置中心
    ├── 平台列表
    │   ├── 配置完整度
    │   ├── 连接状态
    │   ├── 启用状态
    │   └── 配置、测试、启停、删除
    └── 平台配置工作台
        ├── 1 平台信息
        ├── 2 API 供应商
        ├── 3 推广位
        ├── 4 返利配置
        └── 5 检测与启用
```

现有以下菜单入口被“平台配置中心”替换：

- API 供应商管理
- 平台配置
- 推广位管理
- 返利配置

旧页面组件和后端接口本期不立即删除，以降低迁移风险。

## 6. 平台配置中心

### 6.1 查询与筛选

顶部提供：

- “接入新平台”主按钮。
- 平台编码或名称关键词搜索。
- 状态筛选：全部、待完善、可启用、已启用、检测失败。

### 6.2 列表字段

- 平台名称和编码。
- 主供应商。
- 备用供应商数量。
- 运行时默认推广位。
- 平台默认返利比例。
- 配置完整度。
- 最近连接状态。
- 平台启用状态。
- 最近更新时间。

### 6.3 配置完整度

配置完整度由后端聚合计算，包含五项：

1. 平台基础信息完整。
2. 主供应商凭证完整。
3. 至少存在一个启用的运行时默认推广位。
4. 存在当前平台的默认返利规则。
5. 当前草稿版本或当前运行配置的最近连接测试通过。

前端不得自行推导完整度，避免校验规则在多端漂移。

### 6.4 行操作

- 配置。
- 连接测试。
- 启用或停用。
- 删除。

已启用平台必须先停用才能删除。删除操作在一个事务中逻辑删除当前租户、当前平台下的运行平台、供应商、推广位、平台返利规则和未发布草稿；不得删除全平台规则、其他平台规则、历史订单、返利记录、结算记录或审计记录。

## 7. 平台配置工作台

### 7.1 通用行为

- 新增模式按步骤前进，并在切换下一步前校验当前步骤。
- 编辑模式允许直接点击任意页签。
- 用户可以随时保存草稿。
- 页面存在未保存内容时，离开前二次确认。
- 每个步骤显示未配置、待检测、检测通过或检测失败状态。
- 任意影响运行配置的草稿修改都会使之前的检测结果失效。

### 7.2 第一步：平台信息

字段：

- 平台编码。
- 平台名称。
- Logo。
- 平台服务费率。
- 排序。
- 备注。

平台编码必须从后端返回的已注册平台能力列表中选择。系统可以显示尚未配置的平台，但不能把未注册适配器的任意编码发布为可运行平台。

首次接入默认保存为禁用草稿。

### 7.3 第二步：API 供应商

规则：

- 必须配置一个主供应商。
- 可添加多个备用供应商。
- 主供应商和备用供应商编码不得重复。
- 备用供应商支持排序和启停。
- 本期不执行自动故障切换。

字段：

- 供应商编码和名称。
- 供应商类型。
- AppKey。
- AppSecret。
- API 基础地址。
- AuthToken。
- 供应商特有扩展配置。
- 优先级。
- 状态。
- 备注。

供应商凭证字段由后端供应商描述符和配置 Schema 动态驱动。AppSecret、AuthToken 等敏感字段不返回明文；编辑时留空表示沿用已保存值。

主供应商和备用供应商均可单独执行凭证及能力检测。

### 7.4 第三步：推广位

规则：

- 至少存在一个启用的通用推广位。
- 必须明确选择一个运行时默认推广位。
- 可添加渠道专属和用户专属推广位。
- 支持单条新增、编辑、删除和批量导入。
- 淘宝会员推广位继续执行 PID、会员关联和 `specialId` 校验。
- 渠道推广位执行本地渠道与联盟 `relationId/channelId` 的完整性校验。

平台默认推广位和主供应商备用推广位由统一编排服务同步。推广位自身的 `isDefault` 不再作为运行时默认来源，避免三套默认概念冲突。

### 7.5 第四步：返利配置

基础设置仅要求当前平台默认返利比例。

高级设置包括：

- 会员等级。
- 最小返利金额。
- 最大返利金额。
- 优先级。
- 状态。

页面显示规则生效范围和命中顺序说明。用户可为当前平台新增多条等级返利规则，但不能在该工作台创建全平台或其他平台规则。

### 7.6 第五步：检测与启用

展示：

- 平台摘要。
- 主供应商和备用供应商摘要。
- 默认推广位摘要。
- 默认返利及高级规则摘要。
- 缺失项和风险项。

检测顺序：

1. 静态结构和跨配置关系校验。
2. 主供应商凭证及能力检测。
3. 启用的备用供应商凭证及能力检测。
4. 默认推广位一致性检查。
5. 返利规则完整性和冲突检查。

检测失败时允许保存为待完善草稿，平台保持禁用或继续使用旧配置。检测全部通过后，用户可选择：

- 发布但保持禁用。
- 发布并启用。

## 8. 已有平台安全重配

已有平台重配必须遵循“检测通过后再切换”：

1. 从当前四类运行配置生成一份接入草稿。
2. 用户修改只写草稿，不改变运行配置。
3. 检测使用草稿中的新凭证和新关系。
4. 每次修改草稿递增版本并清除旧检测结果。
5. 检测成功后记录草稿版本、配置指纹和检测时间。
6. 发布时校验当前草稿版本和配置指纹与已检测版本一致。
7. 在一个数据库事务中写入四类运行配置。
8. 事务失败全部回滚。
9. 事务提交后清理相关缓存。
10. 运行流量开始使用新配置。

发布前，商品搜索、转链、订单同步和返利结算继续使用旧配置。

## 9. 数据模型

现有运行时表保持不变：

- `cps_platform`
- `cps_api_vendor`
- `cps_adzone`
- `cps_rebate_config`

新增 `cps_platform_onboarding_draft`，建议字段：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `platform_code` | 平台编码 |
| `mode` | `CREATE` 或 `RECONFIGURE` |
| `payload_ciphertext` | 加密后的完整草稿 |
| `draft_version` | 乐观锁版本 |
| `config_fingerprint` | 当前草稿配置指纹 |
| `validated_fingerprint` | 最近检测通过的配置指纹 |
| `status` | `DRAFT`、`VALIDATING`、`READY`、`FAILED` |
| `check_summary` | 结构化检测摘要 |
| `validated_at` | 最近检测通过时间 |
| `tenant_id` | 租户 |
| 审计字段 | 创建人、修改人、时间、逻辑删除 |

唯一约束为当前租户下未删除的 `platform_code` 唯一。

草稿中的敏感凭证必须使用项目统一加密能力保存，不得使用可逆明文 JSON。

`config_fingerprint` 必须根据规范化、加密前的业务配置计算，排除更新时间、随机 IV 等非业务字段。编辑已有平台时，前端提交的空敏感字段表示沿用运行配置或草稿中的密文，不能被合并为空值。

为支持租户隔离和逻辑删除后重新接入，实施时同步修正运行表约束：

- `cps_platform` 使用包含 `tenant_id`、`platform_code` 和 `deleted` 的唯一约束，替换当前仅约束 `platform_code` 的索引。
- `cps_adzone` 增加包含 `tenant_id`、`platform_code`、`adzone_id` 和 `deleted` 的唯一约束。
- 返利规则含可空作用域字段，发布服务使用规范化作用域键执行重复校验和幂等更新，不能依赖 MySQL 对可空列的普通唯一索引。

## 10. 后端接口

统一接口根路径：

```text
/admin-api/cps/platform-onboarding
```

接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/page` | 平台配置中心聚合列表 |
| `GET` | `/get` | 获取运行配置和当前草稿 |
| `POST` | `/draft` | 创建或更新草稿 |
| `DELETE` | `/draft` | 删除草稿，不影响运行配置 |
| `POST` | `/validate` | 执行本地结构校验 |
| `POST` | `/test` | 执行供应商连接和能力检测 |
| `POST` | `/publish` | 发布草稿 |
| `PUT` | `/enable` | 启用已发布平台 |
| `PUT` | `/disable` | 停用平台 |
| `DELETE` | `/delete` | 事务性逻辑删除已停用的平台配置包 |
| `GET` | `/platform-capabilities` | 获取已注册平台能力 |
| `GET` | `/vendor-descriptors` | 获取供应商描述符和配置 Schema |

`CpsPlatformOnboardingService` 负责跨配置校验、草稿管理和发布事务。它复用现有四类 Service，不调用 Controller。

## 11. 发布事务

外部连接测试不得持有数据库事务。连接测试先针对草稿执行并记录通过的配置指纹，发布只接受已检测的当前草稿版本。

发布事务顺序：

```text
校验租户、权限、草稿版本和配置指纹
→ 写入或更新主供应商及备用供应商
→ 写入或更新推广位
→ 写入或更新当前平台返利规则
→ 写入或更新平台，并绑定主供应商和运行时默认推广位
→ 标记草稿已发布
→ 提交事务
→ 事务提交后清理平台、供应商和返利缓存
```

事务内逐条调用推广位保存逻辑，不复用允许部分成功并吞掉单项异常的批量创建方法。

首次接入和已有平台重配使用同一发布服务：

- 首次接入执行受控创建。
- 已有平台执行按稳定业务键匹配的受控更新。
- 重复发布同一草稿版本必须幂等。
- 草稿版本冲突不得覆盖其他用户修改。

## 12. 跨配置校验

发布前必须满足：

- 所有子项 `platformCode` 与根平台编码一致。
- 平台适配器已注册。
- 主供应商存在、启用、配置完整，并具备平台需要的真实业务能力。
- 所有启用的备用供应商均存在对应客户端和能力。
- `activeVendorCode` 指向本次配置中的主供应商。
- 默认推广位属于当前平台且启用。
- 平台默认推广位与主供应商备用推广位保持一致。
- 推广位 ID 在当前租户和平台下不得重复。
- 当前平台只能存在一个运行时默认推广位。
- 默认返利比例在 `0–100`。
- 返利最小和最大金额不得为负，且最小值不得大于最大值。
- 同一平台、会员等级和优先级的返利规则不得重复。
- 统一工作台不得创建 `platformCode=null` 的全平台返利规则。

## 13. 权限

新增权限：

- `cps:platform-onboarding:query`
- `cps:platform-onboarding:create`
- `cps:platform-onboarding:update`
- `cps:platform-onboarding:delete`
- `cps:platform-onboarding:test`
- `cps:platform-onboarding:publish`

平台配置中心菜单使用 `query` 权限。接口分别校验对应动作权限，不能仅凭平台创建权限绕过供应商、推广位和返利配置边界。

旧权限暂时保留，供兼容接口和回滚使用。

## 14. 安全与审计

- 所有草稿、查询、检测和发布均使用登录租户上下文。
- 请求体中的租户 ID 不参与数据归属判断。
- AppSecret、AuthToken 等字段不在响应中返回明文。
- 日志不得记录凭证、完整扩展配置或未脱敏检测请求。
- 检测结果记录供应商、能力、耗时、错误分类和脱敏建议。
- 发布记录操作者、租户、平台、草稿版本、配置指纹、发布结果和失败原因。
- 删除为逻辑删除；历史订单、返利、结算和审计数据保持不变。

## 16. 菜单与迁移

数据库脚本遵循项目约定：

- 新库同步更新 `backend/sql/module/cps-all-in-one.sql`。
- 现有库同步更新 `backend/sql/module/cps-update.sql`，更新块记录修改日期和时间。
- 不创建日期命名或 `backend/sql/mysql` 下的 CPS 脚本。

迁移步骤：

1. 新增草稿表和统一权限。
2. 新增“平台配置中心”菜单。
3. 隐藏四个旧菜单，不立即删除旧权限和后端接口。
4. 读取现有四表生成聚合列表，无需迁移运行配置。
5. 用户首次编辑已有平台时按需生成重配草稿。

## 17. 测试与验收

### 17.1 后端

DB 单元测试覆盖：

- 首次接入草稿和发布。
- 已有平台重配时运行配置保持不变。
- 检测通过后四类配置原子切换。
- 发布任一步失败时全部回滚。
- 重复发布幂等。
- 草稿版本冲突。
- 租户隔离。
- 推广位和返利规则重复校验。
- 默认推广位一致性。
- 发布后的缓存失效。

Mockito 测试覆盖：

- 平台适配器注册校验。
- 供应商配置 Schema 校验。
- 主供应商和备用供应商能力检测。
- 检测结果脱敏。
- 草稿修改后检测状态失效。

Controller 测试覆盖统一权限和请求校验。

### 17.2 前端

Playwright 覆盖：

- 首次接入完整五步流程。
- 连接失败后保存待完善草稿。
- 从配置中心继续未完成草稿。
- 修复凭证后检测并启用。
- 已有平台重配时旧配置继续显示为运行中。
- 草稿测试通过后发布并切换。
- 新增、编辑和删除备用供应商。
- 新增、编辑、删除和批量导入推广位。
- 基础返利和高级返利规则。
- 未保存离开确认。
- 权限不足时按钮和接口均不可用。
- 停用后逻辑删除平台。

最终验收还需执行前端类型检查、ESLint、CPS 目标后端测试和生产构建；若仓库已有无关失败，必须单独记录并提供本功能目标验证证据。

## 18. 成功标准

- 用户从单一入口完成新平台配置，不再跨四个菜单往返。
- 已有平台重配不会在检测通过前影响运行流量。
- 检测失败的配置可以安全保存并继续完善。
- 平台中心能明确展示缺少哪项配置以及失败原因。
- 主供应商、默认推广位和平台默认返利在发布后保持一致。
- 统一入口保留四类配置的查看和增删改能力。
- 所有发布动作具备租户隔离、权限控制、事务回滚、幂等和审计证据。
