# 租户网站 `host[:port]` 校验设计

## 背景

管理后台登录页和注册页使用 `location.host` 查询当前域名绑定的租户。在本地开发环境中，该值包含端口，例如 `127.0.0.1:5173`。当前 Admin 与 App 租户查询接口仅允许字母、数字、点和连字符，导致带端口的合法 Host 在进入 Controller 方法前被 Jakarta Validation 拒绝。

租户绑定数据允许端口参与匹配。修复后必须保留请求中的端口，并继续按完整原始值查询租户，不做去端口或规范化处理。

## 目标

- Admin 与 App 的 `get-by-website` 接口接受合法的 `host[:port]`。
- 端口作为租户绑定键的一部分参与精确查询。
- 保持现有无端口域名、IPv4 地址和单段标识符的兼容性。
- 对端口范围和非法结构提供明确、可复用、可测试的校验。

## 非目标

- 不修改租户绑定数据或 SQL 种子数据。
- 不将 `location.host` 改为 `location.hostname`。
- 不自动添加或删除协议、端口、路径或大小写转换。
- 不在本次修复中增加 IPv6 Host 支持。
- 不重构租户查询或数据库 `FIND_IN_SET` 逻辑。

## 方案

在 `qiji-module-system` 内新增租户网站专用 Jakarta Validation 约束和校验器，由 Admin 与 App 两个 Controller 共同使用。

校验器将输入拆分为 Host 与可选端口：

1. Host 部分沿用现有兼容规则，只允许字母、数字、点和连字符，且不能为空。
2. 最多允许一个冒号，冒号后必须是十进制端口。
3. 端口必须在 `1` 到 `65535` 之间。
4. 校验只决定请求是否可进入 Controller，不改变输入字符串。
5. Controller 将通过校验的原始字符串直接传给 `TenantService.getTenantByWebsite()`，保持精确匹配。

使用模块专用约束而非通用框架约束，是因为租户网站字段还兼容单段应用标识符，不等同于严格 DNS Host；将该规则放入通用框架会产生误导性的复用契约。

## 接口行为

以下输入应通过：

- `www.iocoder.cn`
- `127.0.0.1`
- `127.0.0.1:5173`
- `localhost:5173`
- `wxc4598c446f8a9cb3`
- `host:1`
- `host:65535`

以下输入应被拒绝，并继续返回“网站域名格式不正确”的校验错误：

- 空字符串
- `host:0`
- `host:65536`
- `host:abc`
- `host:`
- `host:80:90`
- `http://host:5173`
- `host:5173/path`
- 含空白的值
- `[::1]:5173`

## 代码边界

- 新增模块内的租户网站校验注解与校验器。
- 修改 `TenantController.getTenantByWebsite()` 的参数约束。
- 修改 `AppTenantController.getTenantByWebsite()` 的参数约束。
- 新增校验器单元测试。
- 不修改前端、Service、Mapper 或数据库脚本。

## 测试策略

采用 TDD：

1. 先为 `127.0.0.1:5173`、边界端口和非法端口编写校验测试，并确认测试因缺少新行为而失败。
2. 实现最小校验器并替换两个 Controller 的重复正则。
3. 运行新增目标测试，确认合法和非法输入矩阵全部通过。
4. 运行 `qiji-module-system` 模块测试，确认现有租户、认证及其他系统模块行为未回归。

## 风险与控制

- 风险：过度收紧 Host 规则可能破坏现有单段应用标识符。控制：Host 部分保持原有字符集合，不引入严格 DNS 标签校验。
- 风险：只修改一个 Controller 会导致 Admin 与 App 行为漂移。控制：两者统一使用同一个约束。
- 风险：校验器意外规范化输入会改变租户匹配。控制：校验器只返回布尔结果，Controller 继续传递原始字符串。

## 完成标准

- `127.0.0.1:5173` 不再触发 `ConstraintViolationException`。
- 合法端口被保留并用于租户精确匹配。
- 非法端口和非法结构仍在 Controller 边界被拒绝。
- Admin 与 App 接口规则一致。
- 新增目标测试和 system 模块回归测试通过。
