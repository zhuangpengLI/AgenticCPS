# 好单库活动转链与订单归因设计

> 日期：2026-07-30
> 状态：已确认
> 范围：好单库淘宝会场、淘宝闪购/饿了么活动转链，会员订单自动归因与订单号申领

## 1. 背景与问题

好单库提供官方活动转链能力：淘宝会场使用 `createConference_code`，淘宝闪购/饿了么会场使用 `elm_activity_ratesurl`。当前实现存在以下断点：

- 好单库活动只接通淘宝会场，淘宝闪购/饿了么活动会被拒绝。
- 活动服务把渠道标识写入 `externalId`，淘宝会场客户端读取的却是 `relationId`，渠道参数没有传给上游。
- 好单库淘宝商品转链没有传递 `relation_id` 或 `special_id`。
- 好单库订单解析把 `special_id`、`relation_id`、`channel_code` 混入 `externalId`，没有填充专用字段，现有可信归因逻辑无法命中。
- 管理端已有 `special_id` 人工绑定能力，但会员端没有通过订单号找回订单的入口。

目标是补齐“登录会员获取活动链接 -> 上游下单 -> 订单同步 -> 可信自动归因 -> 无法自动归因时订单号申领”的闭环，同时避免订单号泄露导致返利冒领。

## 2. 设计原则

- 会员资产归属只使用登录上下文和可验证映射，不信任请求体中的会员 ID。
- `special_id`、`relation_id`、`sid/channel_code` 必须先映射到本地会员，不能直接把任意数字当作会员 ID。
- 订单号是定位订单的索引，不是所有权证明。
- 一个平台订单只能归属一个会员；重复提交必须幂等。
- 已产生返利、冻结、扣减、到账或退款资产活动的订单不得直接改绑。
- 未确认归属的订单可以同步和保存，但不得生成或变更会员返利资产。
- 所有自动归因、申领、审核、拒绝和冲突均写入追加式归因审计日志。

## 3. 方案选择

采用混合方案：有可信证据时自动绑定，只有订单号而缺少可信证据时进入人工审核。

不采用“只凭订单号立即绑定”，因为订单号可能从截图、客服记录或共享设备中泄露。不采用“所有订单均人工审核”，因为可信渠道已经足以自动归因，强制审核会增加运营成本并延迟返利。

## 4. 活动转链设计

### 4.1 会员入口

新增会员端活动推广接口。接口从登录上下文取得会员 ID，不接受请求体 `memberId`。请求只包含活动 ID、可选推广位和终端类型。

管理后台现有活动推广接口继续用于运营生成公共推广内容。公共链接可以统计渠道，但没有会员专属可信标识时不得自动归属到某个会员。

### 4.2 淘宝会场

调用好单库 `POST https://v2.api.haodanku.com/createConference_code`：

- 必传 `apikey`、已授权淘宝账号名 `tb_name`、`activity_id/activity_url`、`pid` 和标题等上游要求字段；缺少 `tb_name` 时直接返回可操作的配置提示，不发送已知无效请求。
- 好单库淘宝会场接口只支持渠道专属 PID 及官方 `relation_id`，不支持 `special_id`。
- `relation_id` 来源于本地已验证推广位配置，不使用本地会员 ID 直接代替。
- 只有该 `relation_id` 已唯一映射到当前会员时才标记为会员可追踪；仅映射到运营渠道时标记为渠道追踪。
- 没有渠道专属配置时仍可生成公共活动链接，但响应明确标记为不可保证会员自动归因。

### 4.3 淘宝闪购/饿了么会场

调用好单库 `POST https://v3.api.haodanku.com/elm_activity_ratesurl`：

- 传入 `apikey`、活动 ID或活动链接。
- 为登录会员生成 1-15 位、仅含字母/数字/下划线的不可逆短 `sid`。
- 本地保存 `sid -> tenantId + memberId + activityId + vendorCode` 的可信映射。
- 不直接使用会员 ID 作为 `sid`，避免标识泄露和跨租户碰撞。
- 上游订单回传 `channel_code` 后，只有它能唯一匹配有效 `sid` 映射时才自动归因。

### 4.4 返回结果

活动推广结果除链接、口令、推广位外，增加归因能力描述：

- `attributionStatus=TRACKABLE`：存在可信会员归因标识。
- `attributionStatus=CHANNEL_ONLY`：只能追踪运营渠道，不能确定会员。
- `attributionStatus=UNTRACKED`：公共链接，不能自动绑定会员。
- `attributionMessage`：说明当前链接下单后的归因方式。

任何返回给浏览器的 URL 必须是有效公网 HTTP(S) 地址，禁止 `localhost`、回环地址和站内开发地址冒充外部活动链接。

## 5. 订单同步与自动归因

### 5.1 好单库订单字段解析

订单适配器应分别填充：

- `specialId`：上游 `special_id/specialId`。
- `relationId`：上游 `relation_id/relationId`。
- `externalId`：`channel_code/sid/external_id` 等外部渠道字段。
- `adzoneId`：`adzone_id/pid/position_id`。
- `orderScene`：上游场景字段，存在时保留。

不能再把 `special_id` 或 `relation_id` 只放入 `externalId`。

淘宝闪购订单通过 `elm_order_list` 拉取，保留 `channel_code`、订单标签、退款和结算相关字段。订单同步权限或上游字段缺失时，订单保持未归因状态。

### 5.2 可信归因优先级

订单同步按以下顺序解析会员：

1. `special_id` 匹配启用的会员专属推广位。
2. `relation_id` 匹配启用且平台一致的外部关系映射。
3. `channel_code/sid` 匹配启用且租户、平台、供应商一致的短标识映射。
4. `adzone_id` 匹配启用的会员专属推广位。
5. 唯一转链记录兜底，仅在平台、商品或活动标识、推广位和有效时间窗均一致时使用。

出现多条候选、跨租户、跨平台、标识失效或仅存在裸数字 `externalId` 时拒绝猜测归因，并写入 `CONFLICT`、`REJECTED` 或 `UNATTRIBUTED` 审计。

## 6. 订单号申领

### 6.1 会员提交

商城“我的 CPS 订单”增加“找回订单”。登录会员提交：

- 平台编码。
- 平台订单号。
- 幂等键由客户端生成或服务端补齐。
- 可选的付款金额、下单时间和商品名称作为审核辅助证据，但不作为单独的自动绑定依据。

接口不接受会员 ID，候选会员始终取登录上下文。

### 6.2 处理流程

1. 精确查询本租户、本平台的平台订单号。
2. 本地不存在时，使用平台供应商能力做定向拉取；若上游不支持订单号过滤，则在受限时间窗和页数内拉取后精确匹配。
3. 上游未找到时返回“订单尚未同步或不属于当前推广账号”，记录失败审计，不暴露其他会员信息。
4. 已归属当前会员时幂等返回 `BOUND`。
5. 已归属其他会员时返回冲突，不透露目标会员身份。
6. 未归属且可信渠道字段映射当前会员时，事务内自动绑定并记录 `CLAIM_AUTO_APPROVED`。
7. 未归属但只有订单号或辅助证据时，创建 `PENDING_REVIEW` 申领记录。
8. 已有同一订单、同一会员的待审核申领时幂等返回原状态。
9. 同一订单存在其他会员申领时标记冲突并交由管理员审核。

### 6.3 审核

复用 `cps_order_attribution_log` 保存申领状态和证据摘要，不创建第二套订单或返利事实表。增加管理端审核操作：

- `APPROVE`：重新锁定订单，确认仍未归属、未发生资产活动，绑定到候选会员并写入审计。
- `REJECT`：保存拒绝原因，不修改订单。
- 订单已绑定、已产生资产活动、租户不一致或状态已经变化时，审核失败并保留冲突记录。

管理员通过已有订单归因日志页面查看和处理待审核申领。

## 7. 并发、幂等与资金边界

- 数据库中 `(platform_code, platform_order_id)` 继续保持订单唯一性。
- 申领使用租户范围内的幂等键；同一键重复请求返回原结果。
- 审核和自动绑定必须在事务中锁定订单并再次检查 `member_id` 与资产活动。
- 绑定更新使用“订单仍未归属”的条件更新，避免两个会员并发抢占。
- 绑定成功只更新订单归因和审计，不直接创建返利资产；正常结算任务后续按订单状态处理。
- 已产生返利记录、冻结记录、资产流水、返利时间或其他资金活动的订单禁止直接改绑。

## 8. 错误与用户提示

- `ORDER_NOT_FOUND`：订单尚未同步、订单号错误或不属于当前推广账号。
- `ORDER_ALREADY_BOUND`：已绑定当前会员，按成功处理。
- `ORDER_CLAIM_CONFLICT`：订单已归属或被其他会员申领。
- `ORDER_CLAIM_PENDING_REVIEW`：缺少可信自动归因证据，等待审核。
- `ORDER_CLAIM_ASSET_LOCKED`：订单已有资金活动，不能直接绑定。
- `ORDER_VENDOR_UNAVAILABLE`：上游订单查询暂不可用，可稍后重试。

接口不得通过错误信息泄露其他会员 ID、昵称、手机号或返利金额。

## 9. 前端交互

### 9.1 商城端

- 在“我的 CPS 订单”页面增加“找回订单”命令入口。
- 使用弹窗或底部面板填写平台和订单号。
- 提交后展示“已找回、待审核、未找到、存在冲突”状态。
- 待审核记录可再次查看，但重复提交不产生新记录。
- 成功绑定后刷新订单列表。

### 9.2 管理后台

- 订单归因日志页支持筛选 `PENDING_REVIEW`。
- 待审核记录提供通过和拒绝命令。
- 审核对话框必须填写审核备注；拒绝必须填写原因。
- 页面不提供直接覆盖已归属会员或绕过资金边界的操作。

## 10. 测试与验收

### 10.1 后端测试

- 淘宝会场转链正确传递 `special_id/relation_id` 和 PID。
- 淘宝闪购转链正确传递合规 `sid`，不暴露会员 ID。
- 好单库订单分别解析 `special_id`、`relation_id`、`channel_code`。
- 四级可信映射的自动归因优先级正确。
- 裸数字 `externalId` 不得直接归属会员。
- 订单号申领在未找到、已绑定当前会员、已绑定其他会员、可信自动通过、待审核场景下返回正确状态。
- 同一订单重复申领幂等。
- 两个会员并发申领只能有一个有效归属。
- 跨租户订单、映射和申领不可互相访问。
- 已产生返利或冻结/资产流水的订单不可直接改绑。
- 审核通过和拒绝均产生完整审计记录。

- 商城订单页可打开找回入口、校验表单、提交并展示各状态。
- 自动绑定成功后订单出现在当前会员列表。
- 待审核不会被展示为已返利。
- 管理后台可筛选、通过和拒绝申领。
- 窄屏和桌面视口下文字、按钮和弹窗不重叠。

## 11. 非目标

- 不把好单库或淘宝联盟订单号当作用户身份凭证。
- 不允许会员直接指定目标会员 ID。
- 不在申领接口中直接创建返利、冻结或资产流水。
- 不自动改绑已归属其他会员或已有资金活动的订单。
- 不把管理后台公共活动推广链接伪装成会员专属可追踪链接。
