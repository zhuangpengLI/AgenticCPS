# 返利工具箱需求设计

> 生成日期：2026-05-23  
> 参考页面：大淘客工具箱 `https://www.dataoke.com/tools?type=14#/toolsCashGift` 与用户截图  
> 当前仓库证据：`frontend/admin-vue3/src/views/cps/goods/rebate-query/index.vue`、`frontend/admin-vue3/src/views/cps/goods/square/index.vue`、`frontend/admin-vue3/src/api/cps/goodsTool.ts`、`frontend/admin-vue3/src/api/cps/goodsSquare.ts`、`backend/qiji-module-cps/qiji-module-cps-biz/src/main/java/com/qiji/cps/module/cps/controller/admin/goods/CpsGoodsRebateQueryController.java`、`backend/qiji-module-cps/qiji-module-cps-biz/src/main/java/com/qiji/cps/module/cps/controller/admin/goods/CpsGoodsSquareController.java`

## 1. 目标

将当前分散的“商品返利查询 / 返利商品广场 / 转链记录”等后台能力升级为一个统一的“返利工具箱”，面向运营人员完成选品、解析、转链、返利预估、推广文案生成、批量复制和记录追踪。

首期目标不是复制大淘客整站，而是复刻其工具箱工作台模式：左侧工具导航、顶部授权/能力提示、中间输入区、右侧转链结果区、底部可继续编辑的推广内容。

## 2. 参考页拆解

参考页提供了以下可借鉴结构：

- 顶部品牌区：工具箱标题、账号入口、授权提醒。
- 左侧分组导航：首页、热门活动、基础工具、玩法工具、创作工具。
- 基础工具：淘宝万能转链、淘口令解析、口令归属检测、拼多多转链、美团外卖转链。
- 玩法工具：创建淘礼金、淘礼金单页。
- 创作工具：制作推广图、编辑微信文案、优惠券查询。
- 主工作区：输入待转链内容，选择联盟账号/PID，执行批量转链或补贴玩法，输出转链结果。
- 结果选项：原格式、淘口令、链接、快站中转等复选配置，并允许手动编辑推广文案。

## 3. 当前差距

当前 AgenticCPS 已具备部分底层能力，但体验仍是单点页面：

- `商品返利查询` 只能单条输入，输出短链、长链、淘口令和移动端链接。
- `返利商品广场` 已支持选品搜索、活动入口、热词、类目、排序、高级筛选和转链弹窗。
- 后端已能解析内容、生成推广链接、写入 `cps_transfer_record`。
- 缺少统一工具箱导航、批量转链、结果格式控制、文案编辑区、授权状态提示、工具之间的流转。
- 缺少“口令解析/归属检测/优惠券查询/推广文案”这类轻量运营工具的明确入口。

## 4. 用户与场景

主要用户：

- 平台运营：批量处理微信群、社群、短视频素材中的商品链接与口令。
- CPS 管理员：检查平台供应商、推广位、会员归因和返利预估是否正确。
- 内容推广人员：从商品广场选品后生成适合微信/社群/短视频的推广文案。

核心场景：

- 粘贴多条淘宝/京东/拼多多/抖音商品链接或口令，批量生成可推广内容。
- 对单条内容做解析，确认商品 ID、平台、佣金、优惠券、返利预估和使用推广位。
- 从商品广场选中商品，一键带入转链工具并生成文案。
- 检查一条淘口令或链接是否属于当前推广位或会员归因。
- 查看最近转链记录，复用历史结果。

## 5. 信息架构

将菜单名称从“返利工具”调整为“返利工具箱”，首期工具分组如下：

| 分组 | 工具 | 首期状态 | 说明 |
|---|---|---|---|
| 基础工具 | 万能转链 | P0 | 单条/批量输入，支持多平台和供应商选择 |
| 基础工具 | 口令解析 | P0 | 解析商品 ID、goodsSign、标题、原链接、平台 |
| 基础工具 | 返利预估 | P0 | 复用现有商品返利查询，展示佣金与会员返利 |
| 基础工具 | 口令归属检测 | P1 | 检查推广位、会员归因、转链记录匹配 |
| 选品工具 | 返利商品广场 | P0 | 复用现有商品广场，支持带入转链 |
| 选品工具 | 优惠券查询 | P1 | 按商品或关键词查券，展示券额、有效期、可用性 |
| 创作工具 | 推广文案编辑 | P0 | 结果可编辑，支持复制短链/淘口令/完整文案 |
| 玩法工具 | 淘礼金 | P2 | 先保留入口和能力说明，后续接淘宝官方/供应商能力 |

## 6. 页面设计

### 6.1 工具箱外壳

页面路径建议：`/cps/toolbox`。

布局：

- 左侧二级工具导航：固定宽度，分组展示工具，当前工具高亮。
- 顶部状态条：展示平台授权状态、默认供应商、默认推广位、批量限制和风险提醒。
- 中间工作区：根据选中工具切换表单。
- 右侧结果区：展示转链结果、解析结果、复制按钮、格式选项。

### 6.2 万能转链

输入：

- 平台：默认自动识别，可手动指定淘宝、京东、拼多多、抖音。
- 会员：后台工具必须选择会员，用于返利归因。
- API 供应商：默认使用平台配置，可临时指定。
- 推广位：默认使用会员或平台默认推广位，可临时指定。
- 原始内容：支持一条或多条链接/口令/商品 ID，每行一条。

输出：

- 每条结果包含平台、商品 ID、标题、券后价、佣金率、预估佣金、预估返利、推广位、供应商、转链记录 ID。
- 链接结果包含短链、长链、淘口令、移动端链接、完整推广文案。
- 支持勾选输出格式：保留原格式、淘口令、链接、短链、移动端链接。
- 支持复制单条、复制全部成功、导出失败原因。

限制：

- P0 每次最多 20 条，与参考页提示保持一致。
- 同一批次失败不阻断其他条目。
- 后端必须逐条写入转链记录，保留失败原因或至少返回失败详情。

### 6.3 口令解析

输入一条原始内容，返回：

- 自动识别平台。
- 商品 ID / goodsSign。
- 原始链接。
- 标题、店铺、图片、券后价。
- 解析来源：本地解析器或平台/供应商解析。

解析成功后可以一键带入万能转链。

### 6.4 返利商品广场

保留当前商品广场能力，但嵌入工具箱：

- 活动入口、热词、类目、排序、高级筛选继续保留。
- 商品卡片操作从“转链弹窗”升级为“带入转链 / 直接转链”。
- 选品结果支持批量勾选后带入万能转链。

### 6.5 推广文案编辑

右侧结果区提供可编辑文本域：

- 默认文案：标题、优惠券信息、短链/移动端链接、淘口令。
- 可以按输出格式勾选动态生成。
- 编辑后复制不回写业务数据；转链原始结果仍以接口返回和转链记录为准。

## 7. 后端需求

P0 后端优先复用现有服务，新增薄接口：

- 单条解析接口：返回解析结果，不强制转链。
- 批量转链接口：接收多条内容，逐条调用现有 `CpsGoodsRebateQueryService.queryRebate()` 或等价服务。
- 批量结果需要包含 `inputIndex`、`originalContent`、`status`、`message`、`goods`、`rebate`、`links`、`transferRecordId`。
- 接口权限建议统一为 `cps:toolbox:query`、`cps:toolbox:link`。

安全约束：

- 后台工具可以选择会员，但必须受后台权限控制并写入操作审计。
- 不改变用户端“不得信任 request body memberId”的边界。
- 不新增资金变更能力；本工具只做查询、解析、转链和记录。
- 所有平台调用失败需要返回可读失败原因，不吞异常成空结果。

## 8. 验收标准

P0 完成后应满足：

- 菜单中展示“返利工具箱”，进入后能看到工具分组和默认“万能转链”。
- 单条转链能力与当前商品返利查询结果一致。
- 批量输入 1 到 20 条内容，成功与失败逐条展示，成功项可复制链接/淘口令/推广文案。
- 商品广场能在工具箱内使用，并能把商品带入转链。
- 会员、平台、供应商、推广位选择逻辑沿用现有页面。
- 后端新增接口有单元测试，前端核心交互有 Playwright 或组件级可验证脚本。
- 不破坏现有 `/cps/goods/rebate-query` 与 `/cps/goods-square/*` 接口。

## 9. 非目标

- P0 不实现真实淘礼金发放。
- P0 不实现快站中转链接服务。
- P0 不新增外部供应商依赖。
- P0 不重做 CPS 结算、冻结、提现或 Token 兑换链路。
- P0 不把后台选择会员能力开放到用户端 API。

## 10. 里程碑

| 阶段 | 目标 | 交付 |
|---|---|---|
| P0.1 | 工具箱壳与菜单 | 新页面、分组导航、状态提示、旧页面能力迁移入口 |
| P0.2 | 万能转链 | 单条/批量转链、格式选项、结果编辑与复制 |
| P0.3 | 商品广场联动 | 商品广场嵌入、商品带入转链、批量选品带入 |
| P1 | 解析与检测增强 | 独立口令解析、口令归属检测、优惠券查询 |
| P2 | 玩法工具 | 淘礼金入口、活动模板、补贴玩法配置 |
